# Risk Analysis Integration Guide

## Overview
This guide documents the integrated approach to risk analysis improvements, ensuring all analysis types consistently capture and store comprehensive recommendation data.

## Standardized Analysis Task Procedure

### 1. Required Fields for All Analysis Tasks
Every analysis task must generate and save the following three recommendation fields:

#### A. `audit_recommendations` (JSONField)
- **Purpose**: Specific audit recommendations and action items
- **Content**: Generated by existing `_generate_*_audit_recommendations` methods
- **Example**: User behavior recommendations, duplicate detection controls

#### B. `compliance_assessment` (JSONField)
- **Purpose**: Compliance risk assessment and regulatory concerns
- **Structure**:
  ```python
  {
      'compliance_risks': {
          'risk_category_1': count,
          'risk_category_2': count,
          # ... specific to analysis type
      },
      'compliance_score': 0-100,  # Higher is better
      'regulatory_concerns': ['concern1', 'concern2', ...]
  }
  ```

#### C. `financial_statement_impact` (JSONField)
- **Purpose**: Financial statement materiality and impact assessment
- **Structure**:
  ```python
  {
      'material_impact': boolean,  # True if any transaction > 1M
      'high_risk_transactions': [transaction_ids],
      'total_anomaly_amount': float,
      'impact_assessment': 'High'|'Medium'|'Low'
  }
  ```

### 3. Standard Implementation Pattern

Each analysis task follows this pattern:

```python
# 1. Generate audit recommendations (existing)
audit_recommendations = self._generate_*_audit_recommendations(...)

# 2. Generate compliance assessment (new)
compliance_assessment = {
    'compliance_risks': {
        # Analysis-specific risk categories
    },
    'compliance_score': max(0, 100 - (anomaly_count * factor)),
    'regulatory_concerns': ['concern1', 'concern2', ...] if anomalies else []
}

# 3. Generate financial statement impact (new)
financial_statement_impact = {
    'material_impact': any(abs(amount) > 1000000 for transaction in anomalies),
    'high_risk_transactions': [transaction_ids with high/critical risk],
    'total_anomaly_amount': sum(abs(amount) for transaction in anomalies),
    'impact_assessment': 'High'|'Medium'|'Low'
}

# 4. Save to database with all three fields
AnalysisResult.objects.create(
    # ... other fields ...
    audit_recommendations=audit_recommendations,
    compliance_assessment=compliance_assessment,
    financial_statement_impact=financial_statement_impact,
    status='COMPLETED'
)
```

### 4. Analysis-Specific Compliance Risk Categories

#### User Analysis
- `high_volume_users`: Users with >100 transactions
- `weekend_activity`: Users with weekend postings
- `manual_entries`: Users with manual entries
- `unusual_accounts`: Users with >20 different accounts

#### Unusual Days Analysis
- `weekend_postings`: Total weekend transactions
- `high_value_weekend`: Weekend transactions >100K
- `unusual_accounts`: Unique accounts used on weekends
- `multiple_users`: Different users posting on weekends

#### Closing Entries Analysis
- `closing_entries`: Total closing period transactions
- `post_close_entries`: Post-close period transactions
- `high_value_closing`: Closing transactions >100K
- `multiple_users`: Different users during closing
- `unusual_accounts`: Unique accounts during closing

#### Duplicate Analysis
- `duplicate_transactions`: Total duplicate pairs
- `high_risk_duplicates`: Duplicates with high/critical risk
- `multiple_duplicate_types`: Different duplicate types found
- `high_value_duplicates`: Duplicates >100K

#### Backdated Analysis
- `backdated_transactions`: Total backdated transactions
- `high_risk_backdated`: Backdated with high/critical risk
- `long_delay_transactions`: Backdated >30 days
- `high_value_backdated`: Backdated >100K
- `multiple_users`: Different users with backdated entries

#### Holiday Analysis
- `holiday_postings`: Total holiday transactions
- `high_value_holiday`: Holiday transactions >100K
- `religious_holidays`: Religious holiday transactions
- `multiple_users`: Different users on holidays

- Celery task time limits increased to 1800 seconds for main risk analysis
- Database queries optimized with select_related/prefetch_related
- Memory-efficient processing for large datasets

### 8. Integration Points

#### A. SAPGLPosting Updates
Individual analysis tasks update specific anomaly flags:
- `is_duplicate`, `is_backdated`, `is_holiday_posting`
- `is_unusual_days_posting`, `is_user_anomaly`, `is_closing_entry`
- Associated risk scores and analysis details

#### B. Overall Risk Analysis
- Only calculates overall risk scores
- Does NOT update individual anomaly flags
- Aggregates results from all 6 analysis types
- Updates `overall_risk_score` on SAPGLPosting records

#### C. Risk Scoring Document
- Creates comprehensive risk assessment document
- Includes all analysis results and recommendations
- Provides executive summary and detailed findings
